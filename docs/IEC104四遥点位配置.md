# IEC 104 四遥点位配置

本文说明如何修改 Protocol Simulator 的 IEC 104 子站工程，包括点表、自动上报和控制反馈绑定。完整的工程结构与 Linux 启动方式见 [README](../README.md)。可从 [IEC 104 子站示例](../examples/server-iec104.json) 了解 JSON 结构。

## 点表

先在工程的 `channels[].devices[]` 中按通道和装置 ID 找到目标装置。点位以 `kind` 和 `address` 组合标识，同一装置内的组合必须唯一。

| 类型 | kind | 用途                         |
| ---- | ---- | ---------------------------- |
| 遥信 | `yx` | 上报开关状态，可作为遥控反馈 |
| 遥测 | `yc` | 上报测量值，可作为遥调反馈   |
| 遥控 | `yk` | 接收主站的开关命令           |
| 遥调 | `yt` | 接收主站的设定值或步调节命令 |

下面是一组可加入装置 `points` 的示例。按实际工程调整地址，并与主站的公共地址、信息体地址和类型对应。

```json
[
  { "kind": "yx", "address": 1, "name": "开关状态", "wireType": 1, "value": 0, "quality": 0 },
  {
    "kind": "yc",
    "address": 16385,
    "name": "功率反馈",
    "wireType": 13,
    "value": 25.5,
    "quality": 0
  },
  { "kind": "yk", "address": 24577, "name": "开关命令", "value": 0, "quality": 0 },
  { "kind": "yt", "address": 24833, "name": "功率设定", "value": 25.5, "quality": 0 }
]
```

- `value` 是工程保存的初始值。已配置的自动变化规则可在运行时覆盖它。
- 普通单点遥信用 `wireType: 1`，状态为 0 或 1。双点遥信用 `wireType: 3`，正常位置为 1 或 2。
- 短浮点遥测用 `wireType: 13`。归一化遥测有独立的取值范围，应按主站映射配置。
- 遥控、遥调点可省略 `wireType`，实际命令类型由主站请求指定。
- 修改地址或类型时，同时更新自动规则、控制反馈绑定和主站映射中的引用。

## 自动变化与定时上报

在目标装置的 `dataTests.telemetry.rules` 中添加规则。仅需初始值时，填写点位的 `value` 即可。

以下示例每五分钟上报遥测点 16385 的当前值，即使值未变化也会发送。规则只选择已有点位。

```json
{
  "enabled": true,
  "kind": "yc",
  "points": "16385",
  "intervalMs": 300000,
  "mode": "report",
  "cause": 1
}
```

`points` 可填单点、范围或逗号分隔的组合。未填 `points` 时使用 `start`、`end` 的含首尾范围。`intervalMs` 的单位为毫秒，范围为 200–3600000。自动变化模式和参数见 [README 的自动规则说明](../README.md#自动数据与上报规则)。

同类型的启用规则中，变化规则之间以及定时上报规则之间分别不得重叠。同一点可以同时配置一条变化规则和一条定时上报规则。Linux 服务需允许启动自动规则，IEC 104 还要求主站连接并完成 STARTDT 激活。

## 遥控与遥调反馈

在同一装置的 `configuration.controls` 下配置 `yk` 和 `yt`。下面的示例对应上面的四个点位。装置还没有 `configuration` 时，可使用下面的对象。已有该字段时，只合并所需的 `controls` 条目，保留其他配置和映射。

```json
{
  "version": "标准版",
  "controls": {
    "yk": {
      "mode": "normal",
      "delayMs": 0,
      "mappings": [
        {
          "source": {
            "kind": "yk",
            "address": 24577
          },
          "target": {
            "kind": "yx",
            "address": 1
          },
          "invert": false
        }
      ]
    },
    "yt": {
      "mode": "normal",
      "delayMs": 0,
      "mappings": [
        {
          "source": {
            "kind": "yt",
            "address": 24833
          },
          "target": {
            "kind": "yc",
            "address": 16385
          }
        }
      ]
    }
  }
}
```

- 遥控映射的目标是遥信。需要反向反馈时，使用 `invert: true`。反馈值按目标点的单点或双点类型编码。
- 遥调映射的目标是遥测。设定值须能由目标点的类型表示。归一化设值原码与工程量需按主站和点位配置分别处理。
- `normal` 正常应答并在有效执行时更新绑定反馈，`deny` 否认命令，`silent` 不应答。`delayMs` 的范围为 0–60000。
- 如果反馈点也被固定值、递增、随机或翻转规则覆盖，下一轮规则可能改写反馈。需要持续保留控制结果时，可将该点从变化规则中移除，按需要保留定时上报。

## 保存并加载

在 Linux 上，先确认实际运行工程的 JSON 路径，在同目录创建副本。完成编辑后对副本执行配置校验。

```bash
prs validate project.editing.json --json
```

校验通过后，确认运行文件在编辑期间未被其他操作修改，备份原文件，再用同目录的已校验副本替换。使用默认热加载时，现有服务会加载新配置。禁用热加载时，按原有服务管理方式重启对应工程。Linux 安装、systemd 和启动参数见 [README](../README.md)。
